## Сохранённые материалы

- `data/places-audit.csv`: строка для **каждого** итогового места — статус, дата, источник.
- `data/original-places.json`: неизменённые исходные 432 записи.
- `data/official-catalogs.json`: нормализованные официальные записи, ссылки и дата снимка.
- `data/catalog-comparison.json`: сопоставление исходных записей, расхождения координат, отсутствовавшие точки.
- `data/update-summary.json`: изменения адресов, сети и итоговые счётчики.

У статуса `listed` подтверждено наличие адреса на официальном сайте на дату снимка. У `unverified` нет достаточного подтверждения: отсутствие на сайте не доказывает закрытие. Эти точки остаются доступны с явной пометкой. Наличие Wi-Fi, свободных мест и разрешения работать с ноутбуком по каждому заведению не проверено; приложение больше не обещает это автоматически.

При расхождении координат более 150 м сохранена прежняя точка и добавлена заметка; такие маршруты стоит проверить отдельно. По адресам из официального каталога можно найти заведение даже при неточном маркере. Ни часы работы, ни коммерческий статус не выдумываются.

Повторная загрузка My Maps теперь формирует `data/import-candidates.json` и не перезаписывает проверенную базу. Скрипты `fetch-*`, `parse-official-catalogs.mjs`, `refine-catalog-details.mjs`, `compare-catalogs.mjs` документируют эту конкретную сверку; их HTML-парсеры и ручные уточнения необходимо пересмотреть при будущей смене сайтов. Они не являются автоматическим мониторингом закрытий.

## Верификация и навигация через Google Places API

Для подтверждения актуальности заведений и повышения точности пешей навигации реализован пайплайн сверки каталога через Google Places API (New) и маршрутизации к объектам POI.

### Принцип работы аудита (`npm run audit:places`)

Скрипт `scripts/audit-google-places.mjs` выполняет автоматизированную сверку всех заведений из `src/data/places.json`:
1. **Формирование поискового запроса**: для каждой точки очищается адрес (отсекается суффикс района через `·`) и составляется запрос вида `<сеть|название> <адрес> Barcelona`.
2. **Запрос к Google Places API (New)**: выполняется вызов `places:searchText` с маской полей (`id`, `displayName`, `formattedAddress`, `location`, `businessStatus`, `googleMapsUri`, `rating`, `userRatingCount`) и круговым гео-ограничением (`locationBias`) радиусом 150 метров вокруг исходных координат.
3. **Кэширование**: результаты запросов сохраняются в `.cache/google-places-cache.json`, предотвращая повторные платные запросы к API.
4. **Сопоставление координат (Haversine)**: скрипт находит ближайшего кандидата и вычисляет расстояние по формуле гаверсинусов:
   - Если ближайший кандидат находится в пределах 150 м, он считается совпадением.
   - Если кандидат дальше 150 м, регистрируется `DISTANCE_MISMATCH` для ручной проверки.
   - Если результатов нет, фиксируется `NOT_FOUND`.

### Выявление закрытий заведений

Google Places API возвращает поле `businessStatus`, позволяющее отслеживать актуальный статус точек:
- `OPERATIONAL` — заведение работает в штатном режиме.
- `CLOSED_TEMPORARILY` — заведение временно приостановило работу.
- `CLOSED_PERMANENTLY` — заведение закрыто навсегда.

Все обнаруженные закрытия и расхождения заносятся в структурированный отчёт `docs/data/google-places-audit.json`. Скрипт не удаляет закрытые точки автоматически во избежание ложных срабатываний: разработчику выводятся предупреждения с требованием явной ручной валидации перед удалением из каталога.

### Обогащение базы (`npm run audit:places:apply`)

При запуске с флагом `--apply` для подтверждённых действующих заведений (`OPERATIONAL`) в `src/data/places.json` добавляются поля:
- `googlePlaceId`: уникальный идентификатор места в Google Maps (например, `ChIJ...`). Корректность формата проверяется регулярным выражением в `scripts/check-places.mjs`.
- `googleMapsUrl`: каноническая ссылка на карточку заведения в Google Maps (`googleMapsUri`).

### Навигация к POI в мобильном приложении

При нажатии на кнопку «Маршрут» («Directions») в приложении утилита `src/utils/directions.ts` генерирует Google Maps Universal Directions URL:
- **При наличии `googlePlaceId`**: формируется URL с параметрами `destination=<Name, Address>&destination_place_id=<PlaceId>&travelmode=walking`. В этом случае Google Maps открывает не безымянную булавку на координатах, а официальную карточку заведения (POI) с актуальным графиком работы, загруженностью и отзывами.
- **При отсутствии `googlePlaceId`**: срабатывает обратная совместимость с переходом по координатам (`destination=<lat>,<lon>&travelmode=walking`).
