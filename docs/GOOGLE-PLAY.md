# Подготовка Google Play

## Настроено в проекте

- `com.workablebcn.app`, Workable BCN, версия 1.1.1. ID существующего EAS-проекта и владелец сохранены.
- Expo 57.0.21, React Native 0.86.3; Android target SDK 36. С 31 августа 2026 Google Play требует API 36 для новых обычных Android-приложений и обновлений: [требование Google](https://support.google.com/googleplay/android-developer/answer/11926878).
- `production`: AAB, увеличение versionCode на стороне EAS (`appVersionSource: remote`). `preview`: APK для установки на телефон.
- `submit.production`: internal track, **draft**. Команда отправки сама не выпускает публичный релиз.
- Новая иконка 1024×1024, adaptive icon с безопасным центральным знаком, Play icon 512×512, feature graphic 1024×500 (`store-assets/feature-graphic.png`) и экран запуска. Тематическая monochrome-иконка необязательна и пока не добавлена.
- Только foreground coarse/fine location. Фоновая геолокация, запись аудио, доступ к внешнему хранилищу и overlay permission заблокированы. Android backup отключён: избранное задумано как локальные данные.
- Интерфейс полностью на английском. About содержит сведения о данных, ссылку на опубликованную политику и email поддержки `workable.bcn@iegorov.com`.

## Сборка

Node.js 22.13+; учётная запись Expo с доступом к существующему EAS-проекту.

```sh
npm ci
npm run typecheck
npm test
npm run check:places
npx expo-doctor
npm run export:android
npx eas-cli@latest login
npm run build:apk
npm run build:android
```

EAS предложит использовать существующий Android upload keystore либо создать его. Не заменяйте ключ опубликованного приложения. Для нового приложения используется Play App Signing; сохраняйте доступ к EAS и upload key.

Android-проект генерируется из app.json (`npx expo prebuild --platform android --no-install`), поэтому правки релизных разрешений вносятся в app.json. Не редактируйте сгенерированный манифест вручную.

## Политика и оставшиеся шаги

Политика опубликована: **https://iegorov553.github.io/workable-bcn-privacy/**. Email: **workable.bcn@iegorov.com**. Публичная страница проверена без авторизации (HTTP 200); её исходник хранится в `docs/privacy-policy.html` и в отдельном репозитории `iegorov553/workable-bcn-privacy`. Код приложения в этот репозиторий не загружался. Отображаемое имя разработчика для Play Console остаётся на выбор владельца.

Также нужны действия владельца аккаунта:

1. Создать карточку приложения в Google Play Console, подтвердить аккаунт и указать контакты.
2. Заполнить возрастную категорию, целевую аудиторию, отсутствие рекламы, категорию и Data safety. Отсутствие аккаунтов в приложении позволяет тестировать без логина.
3. Загрузить иконку, feature graphic 1024×500 и не менее двух **настоящих Android-скриншотов**. Браузерные preview не считаются проверкой native-сборки. Убедитесь, что скриншоты соответствуют текущему интерфейсу и не обещают всеобщую проверку кофеен.
4. Вручную загрузить первый AAB. Для первой отправки Play требует ручную загрузку хотя бы одного билда, затем можно использовать EAS Submit: [инструкция Expo](https://docs.expo.dev/submit/android/).
5. Для последующих отправок настроить Google Service Account через `npx eas-cli@latest credentials --platform android`. Не хранить JSON-ключ в репозитории. После настройки: `npm run submit:android` и выбор нужного AAB.
6. Для новых личных аккаунтов, на которые распространяется правило Google, требуется закрытое тестирование с минимум 12 участниками в течение 14 непрерывных дней перед заявкой на production-доступ: [условия Google](https://support.google.com/googleplay/android-developer/answer/14151465). Internal testing само по себе это требование не выполняет.

## Data safety: фактическое поведение

Это карта обработки данных для заполнения формы, а не уже поданная декларация. Google требует учитывать сторонние сервисы: [Data safety](https://support.google.com/googleplay/android-developer/answer/10787469).

| Данные | Обработка |
|---|---|
| Координаты устройства | Только по нажатию кнопки; остаются в памяти приложения, используются для сортировки и камеры; не сохраняются в историю. |
| Просматриваемая область и IP | HTTPS-запросы тайлов OpenStreetMap. После центрирования область может раскрывать местонахождение. [Политика OSMF](https://osmfoundation.org/wiki/Privacy_Policy). Нельзя автоматически выбрать «ничего не собирается» только потому, что у приложения нет собственного сервера. |
| Избранное | AsyncStorage на устройстве; без облачной синхронизации; Android backup отключён. |
| Маршрут | По действию пользователя открывается Google Maps с адресом/координатами выбранной кофейни. Собственная координата пользователя в URL не добавляется. Google Maps может отдельно запросить её. |
| Регистрация / реклама / аналитика | Не реализованы. |

Проверьте хранение запросов и применимость исключений для передачи по инициативе пользователя / service provider, прежде чем отправлять форму. Не утверждайте отсутствие передачи данных при использовании внешних тайлов.

## Проверка готового Android-артефакта

- Холодный запуск online и offline, отсутствие бесконечной загрузки иконок/шрифтов.
- Allow precise / approximate location, Deny, повторный Deny, выключенный GPS; понятное восстановление через настройки.
- Разрешить позицию, сдвинуть карту пальцем, повторно нажать геолокацию; повторить с открытой карточкой.
- Избранное после перезапуска; фильтры, поиск без диакритики, системный Back, длинные адреса, крупный системный шрифт.
- Маршрут и ссылки источников открываются из реального APK/AAB.
- Проверить final merged manifest и targetSdk 36, отсутствие запрещённых разрешений.
- Проверить Play pre-launch report и нативные библиотеки на устройстве/эмуляторе с 16 KB страницами. [Требование 16 KB](https://developer.android.com/guide/practices/page-sizes). Expo Doctor и JS export не доказывают совместимость всех `.so` конкретного AAB.
- Подтвердить право на использование исходной базы и соблюдение условий источников. Публичная доступность списка сама по себе не равна лицензии на его переиздание. Карта сохраняет атрибуцию OpenStreetMap.
