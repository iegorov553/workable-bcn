# Ревью Workable BCN — 11 сентября 2026

## Исправления

- **P1 — сбой запуска карты в Expo Go с предупреждением `ExpoDomWebViewModule`.** В SDK 57 DOM-компоненты по умолчанию выбирают новый `@expo/dom-webview`; нативное представление недоступно в среде пользователя. Карта явно переключена на `react-native-webview` 13.16.1 через `dom.useExpoDOMWebView: false`, пакет установлен версионным `expo install`. Это официальный способ переключения: [Expo DOM](https://docs.expo.dev/guides/dom-components/), [WebView в Expo Go](https://docs.expo.dev/versions/v57.0.0/sdk/webview/). Проверка на телефоне после перезапуска Metro ещё требуется: устройство не подключено по ADB.

- **P1 — возврат к геолокации не двигал карту.** `App.tsx` обновлял только точку пользователя, а камера реагировала только на выбор кофейни. Добавлена отдельная команда камеры с последовательным номером: повторное нажатие работает даже при одинаковых координатах, предыдущая анимация останавливается, выбранная карточка закрывается. Пересоздание объектов при передаче через Expo DOM не вызывает лишний перелёт.
- **P1 — регрессия Hermes в установленном React Native 0.86.0.** Expo Doctor обнаружил проблемную версию Hermes V1. Зависимости выровнены на Expo 57.0.21 / React Native 0.86.3, `expo-location` 57.0.16.
- **P2 — GPS мог оставлять вечный индикатор.** Ожидание координат ограничено 15 секундами; отказ доступа, выключенные сервисы, ошибка и тайм-аут показываются в интерфейсе. Поздний результат не меняет карту. Повторный запрос защищён от двойного нажатия. На web запрашивается свежая позиция с `maximumAge: 0`, без двойного запроса Expo permissions + GPS.
- **P2 — элементы управления скрывались за Leaflet на web.** Проверка браузером выявила конфликт слоёв: исправлена изоляция stacking context карты.
- **P2 — ошибка шрифта блокировала весь экран.** Удалено ожидание внешних шрифтов, использована системная типографика, пакеты ненужных гарнитур удалены.
- **P2 — карточка оставалась после изменения поиска.** Выбор теперь сверяется с текущей выдачей. Изменение сети закрывает выбор.
- **P2 — ошибки хранилища и некорректное избранное.** Проверяются типы записей и существование ID, записи в хранилище выполняются последовательно, ошибки выводятся пользователю. Исходные 432 ID сохранены, в том числе при исправлении сети.
- **P2 — повторный импорт затирал проверенную базу.** Импорт My Maps теперь пишет только файл кандидатов. Добавлены тайм-аут, проверки координат, пустого результата и дублирующихся ID.
- **P2 — некорректный каталог.** Исправлена сеть для Gignàs, 25 (Buenas Migas вместо Sandwichez), сверены адреса и угловые входы, добавлены отсутствовавшие точки. Источники и ограничения приведены в `CAFE-AUDIT.md` и CSV.
- **P3 — поиск требовал диакритики.** Gracia / Gràcia, cafe / Café и варианты апострофов теперь совпадают.
- **P3 — системная кнопка Back завершала приложение при открытой карточке.** Теперь сначала закрывается карточка, затем происходит возврат с другого раздела на карту.
- Обработаны сбои открытия маршрута и загрузки тайлов, исправлена численная устойчивость расстояний, убраны дубли разрешений Android.

## Проверка и пределы

Исправление пустой карты после повторного отчёта с устройства: кодирование кавычек устранило воспроизводимый дефект передачи строк, но ошибка Expo DOM сохранилась. Карта переведена на обычный react-native-webview с встроенным HTML/Leaflet/CSS и передачей состояния после ready/loadEnd; Expo DOM больше не используется. На web тот же документ работает в iframe. Добавлены тайм-аут загрузки и Retry map. Проверены 13 тестов, TypeScript, Android-экспорт без DOM bundle и CSS asset warnings; браузером проверены карта, фильтрация и переход из списка к выбранной точке. Устройство/эмулятор не подключены, проверка физического Android остаётся необходимой.

Финальный результат: TypeScript без ошибок; 8/8 регрессионных тестов; проверка 520 записей и сохранения всех 432 исходных ID; Expo Doctor 21/21; Android prebuild и Android JS/DOM export успешны. Web export также проверен. Сгенерирован Android-манифест с нужными foreground-разрешениями, отключённым backup и светлой темой; базовый targetSdk установлен в 36. Подписанный AAB не собран.

Регрессионные тесты проверяют повторный возврат к одинаковым координатам, отказ разрешений, отключённую геолокацию, неверные координаты, тайм-аут и поздний результат, валидацию избранного, поиск и расстояния. Проверка данных контролирует уникальность ID, координаты, статусы, источники и сохранение всех старых ID.

Браузерная проверка на размере 390×844: карта и кнопки, фильтры, список, карточка, её закрытие при несовпадающем поиске, избранное и восстановление после перезагрузки, удаление избранного и пустое состояние. В журнале финальной вкладки была ошибка стороннего Chrome extension; ошибок приложения в нём не обнаружено. На настольном компьютере успешная GPS-позиция не получена: проверено корректное завершение по тайм-ауту. Это не заменяет тест GPS и разрешений на физическом Android.

Экспорт JavaScript/DOM для Android не является подписанным AAB. Перед публикацией нужны EAS-сборка и проверка устанавливаемого артефакта на устройстве, включая холодный запуск, системную кнопку Back, offline, геолокацию и совместимость 16 KB. См. `GOOGLE-PLAY.md`.

`npm audit fix` и обновление Expo устранили обнаруженные high severity предупреждения. Остаются 11 moderate предупреждений в цепочке инструментов Expo → xcode → uuid. Не применялся `--force`, предлагающий несовместимое понижение SDK. Исходная причина: [uuid buffer bounds advisory](https://github.com/advisories/GHSA-w5hq-g745-h8pq). Это не означает доказанную уязвимость исполняемого приложения, но предупреждения остаются и требуют отслеживания исправления upstream.
